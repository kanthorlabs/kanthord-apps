# EPIC 002 — App composition

Status: **ready**. Re-authored on 2026-08-10 around a daemon registry. Read "What changed" before you
read the Stories.

`lib/app/` has no dependency injection and no router, and `kanthord_app.dart` still opens the
gallery. This epic wires the SDK into the app and stores the daemons the human configures. It exists
so that EPIC 003 is a running application and not a library test.

## What changed, and why

The first draft stored one base URL under one key and one token under one key. The owner decided the
product holds **more than one daemon** — a local one on the development machine and a remote one on a
VPS — so the app stores a registry of named daemons and selects one. Nothing was implemented against
the scalar draft, so this is a re-author rather than a migration.

Two consequences reach outside this epic and are owned elsewhere:

- `lib/api/` resolves one daemon per request and pins its id, so a base URL and a token can never
  come from two different daemons. **EPIC 001.1** owns that.
- The list, the switcher and the add/remove controls are a screen. **EPIC 003.1** owns that, and it is
  mandatory: until it ships the product holds a registry of one and multi-daemon is not delivered.

## Goal

- **G1** — `get_it` registers `KanthordApi` one time as a lazy singleton, plus `DaemonRegistryType`,
  `DaemonCredentialStoreType` selected per platform, and one `SelectedDaemonProvider` registered under
  both `BaseUrlProviderType` and `TokenProviderType`. Both registrations resolve the **same instance**,
  so the two interceptors of EPIC 001.1 read one registry.
- **G2** — `lib/app/token/` holds `DaemonCredentialStoreType` with `read(daemonId)`,
  `save(daemonId, token)` and `delete(daemonId)`, in two implementations: `flutter_secure_storage` on
  native under the key `kanthord.daemon_token.<id>`, and an in-memory map on web. Neither writes a
  token to `shared_preferences` and neither writes it to `localStorage`.
- **G3** — `lib/app/settings/` holds `Daemon` — `id`, `name`, `baseUrl`, `confirmedAt` — and
  `DaemonRegistryType` over `shared_preferences`: `list()`, `add(name, baseUrl)`, `update(daemon)`,
  `remove(id)`, `select(id)`, `selectedId()` and `selected()`. `list()` returns insertion order, so
  the same input always renders the same list. `id` is generated by the registry, opaque, and never
  changes; `name` and `baseUrl` are editable.
- **G4** — **No daemon selected is a normal state, not a crash.** `selected()` answers `null` after a
  first run that has not seeded, after the selected daemon is removed, and after a stored selected id
  no longer matches an entry. The app renders that state. Nothing throws a `StateError`.
- **G5** — **The first run seeds one daemon and confirms nothing.** When the registry is empty it
  inserts `local` at `Env.apiEndpoint` and selects it, with `confirmedAt` null and no token. The
  convention reaches the human as a prefilled, editable field, and only a `200` from
  `GET /v1/health` sets `confirmedAt`. EPIC 003 owns that probe. The store still invents no value on
  any later run.
- **G6** — `remove(id)` deletes the daemon's credential. A successful removal leaves no orphan token,
  and a failed credential delete fails the removal rather than dropping the entry.
- **G7** — `go_router` replaces `home: KDGalleryPage(...)`. The router declares the boot route, the
  unauthorized route and a development gallery route. Every route is `@TypedGoRoute`, and
  `make arch-check` proves no `Navigator.push` anywhere.
- **G8** — `lib/app/env/` holds the `envied` classes and a committed `.env.example`. `.gitignore`
  ignores `.env*` and admits `.env.example`, so the example is the reproducible artifact and the two
  real files are per-developer. No env file holds a daemon token or a server secret.
- **G9** — The development host is Chrome. `make dev` runs the app at `http://localhost:8080` with the
  port pinned in the `Makefile`, and no gate and no story needs a simulator or an emulator. The daemon
  side is `KANTHORD_HTTP_ALLOWED_ORIGINS=http://localhost:8080`, which the engine already implements.
- **G10** — The cleartext posture of `docs/api/connectivity.md` lands: Android and iOS permit
  cleartext to any host in every build variant, and `scripts/platform-config-check.sh` asserts the
  permission is present on both.

## Non-goals

- No daemon list screen, no switcher and no add or remove control. **EPIC 003.1** owns every one of
  them. This epic ships the store and the seed, and nothing renders a second daemon.
- No feature page and no product route. EPIC 003 owns the first one. The boot route renders a status
  view and nothing more.
- No probe and no health call. The registry never calls a daemon, so it never sets `confirmedAt`
  itself.
- No migration from the scalar draft. Nothing was implemented against it.
- No host-scoped cleartext exception. A build-time file cannot name a host the human types at
  runtime, and the decision is a broad permission instead. Read the cleartext section of
  `docs/api/connectivity.md`.
- No daemon token in any env file. A web build ships readable JavaScript.
- No default base URL in production code beyond the seed of G5. A compile-time development default
  from `envied` is allowed, and it is never a silent fallback on a later run.
- No simulated entry point, no simulation marker and no capability reporting. EPIC 004 delivers the
  release-safety half.
- No new dependency. Every package this epic needs is in `pubspec.yaml`.
- No new `KD` component.

`scripts/platform-config-check.sh` is written by this epic and it proves one grep per mobile target:
the cleartext permission is declared. It cannot prove a build-time file admits a runtime host, and it
claims no such thing.

Hermetic coverage required beyond the Proof:

- The injection root registers `KanthordApi` one time. A second `getIt<KanthordApi>()` returns the
  same instance, and `getIt<BaseUrlProviderType>()` and `getIt<TokenProviderType>()` are
  `identical`.
- The credential store test asserts a token written under one daemon id is not readable under
  another, that `delete` removes it, and that the web implementation loses every token when the
  instance is discarded.
- The registry returns an empty list before any write, preserves insertion order across a reload, and
  keeps `id` stable when `name` and `baseUrl` are edited.
- `selected()` answers `null` when the stored selected id matches no entry, and the app renders that
  state rather than calling a daemon.
- The seed runs one time. A second start with a non-empty registry adds nothing and re-selects
  nothing.
- No file under `lib/` imports a path under `test/`. `scripts/arch-check.sh` gains this rule and its
  self-test in `scripts/arch-check.test.sh`.
- The router test asserts every declared route is typed. `arch-check` proves the absence of
  `Navigator.push` and proves nothing about the route declarations, so the two checks are separate.

`NEEDS-HUMAN:` a real launch. **Chrome at the pinned port is the one that gates this epic**, because
it is the development host. macOS, a physical device, Windows and Linux are carried forward and none
of them blocks the epic. `make verify` is headless and boots no browser.

## Stories

- **The `Daemon` model** — `id`, `name`, `baseUrl`, `confirmedAt`. `@freezed` plus
  `@JsonSerializable`, because the registry persists a JSON list. It lives in `lib/app/settings/`,
  not in `lib/api/models/`: it is app configuration and no daemon route returns it.
- **The credential store** — `DaemonCredentialStoreType` and the two implementations, keyed per
  daemon id, selected by `kIsWeb` at the registration site and never inside the SDK.
- **The daemon registry** — `DaemonRegistryType` and `PreferencesDaemonRegistry` over two
  `shared_preferences` keys: the JSON list and the selected id. It holds the insertion-order rule, the
  unselected state of G4, the seed of G5 and the credential-deleting removal of G6.
- **The selected-daemon provider** — one `SelectedDaemonProvider` implementing both
  `BaseUrlProviderType` and `TokenProviderType` of EPIC 001.1. `endpoint()` maps the selected `Daemon`
  to a `DaemonEndpoint`; `tokenOf(id)` reads the credential store; `baseUrl()` and `token()` serve the
  selected daemon for a caller that does not pin.
- **The injection root** — `lib/app/injection.dart` registers the registry, the credential store, the
  one provider instance under two interfaces, `ApiConfig` and `KanthordApi`. It is the one file that
  names a concrete type. `main()` awaits the seed before `runApp`.
- **The desktop-first check** — every page this epic renders is verified at `expanded` first, in the
  browser, then at `wide` and `mobile`. Read `AGENTS.md` and `DESIGNS.md`.
- **The router** — `lib/app/router.dart` with the boot route, the unauthorized route and the
  development gallery route. `make generate-lib` writes the `go_router_builder` output and the result
  is committed.
- **The env classes and `.env.example`** — `envied` for the development base URL, which is
  `http://localhost:31415`, and nothing else. A test asserts no env key is named like a token, and a
  test asserts the value reaches the app as the G5 seed rather than as a fallback on a later run.
- **The `lib` must not import `test` rule** — the `arch-check` addition and its self-test.
- **The platform posture** — the Android network security configuration and the iOS ATS entry, each
  permitting cleartext to any host in every variant, plus `scripts/platform-config-check.sh`. Whether
  each platform actually blocks a Dart socket is a device measurement and a `NEEDS-HUMAN:` item,
  never an assumption.
